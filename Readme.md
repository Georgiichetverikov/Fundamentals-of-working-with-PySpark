# 🏭 Промышленный мониторинг IoT-телеметрии

Проект представляет собой пайплайн обработки и анализа данных телеметрии промышленного оборудования с использованием **Apache Spark**, **DuckDB** и визуализацией результатов в интерактивном дашборде на **Streamlit**.

---

## 🛠 Технологический стек

* **Язык программирования:** Python 3.10+
* **Обработка данных (ETL):** Apache Spark (PySpark)
* **Аналитические запросы и витрины:** DuckDB
* **Визуализация и UI:** Streamlit, Plotly Express
* **Формат хранения:** Apache Parquet (с партиционированием по дате)

---

## 📐 Архитектура и этапы обработки

1. **Загрузка и валидация данных:**
   * Чтение исходных CSV-файлов телеметрии (`telemetry_*.csv`) по строго заданной схеме (`StructType`).
   * Обогащение данных метаинформацией о файлах-источниках.

2. **Обогащение контекстом:**
   * Объединение телеметрии со справочниками оборудования, производственных линий, датчиков и проведённого технического обслуживания.

3. **Оконный анализ и детектирование аномалий:**
   * Расчёт межизмерительных изменений (`delta`) и скользящих средних (`moving_avg_10`).
   * Фильтрация качественных измерений (`quality = 'good'`) для расчёта средних значений и стандартных отклонений по типам оборудования и датчиков.
   * Определение статистических аномалий на основе показателя $Z$-score ($\vert{}Z\vert{} \ge 3.0$).

4. **Формирование Parquet-витрин:**
   * Очищенные и обогащенные данные сохраняются в `/app/output/clean_telemetry` с партиционированием по `event_date`.
   * Расчёт и сохранение агрегированных витрин: `source_file_kpi`, `line_kpi`, `hourly_metrics`, `sensor_anomalies`, `equipment_kpi`, `maintenance_effect`.

5. **Расчёт бизнес-задач (DuckDB):**
   * **Вариант 5:** Анализ доли некачественных и сомнительных измерений (`bad` / `suspect`) в разрезе линий и цехов (`variant_5_kpi.parquet`).
   * **Вариант 10:** Формирование профиля скоростей вращения (RPM) по типам оборудования (`variant_10_kpi.parquet`).

6. **Визуализация (Streamlit):**
   * Интерактивный дашборд с вкладками для контроля импорта файлов, анализа KPI линий, почасовой динамики и демонстрации результатов по Вариантам 5 и 10.

```text

│   ├── production_lines.csv  # Справочник линий

│   ├── sensors.csv           # Справочник датчиков
│   └── maintenance.csv       # Справочник обслуживания
├── output/                   # Генерируемые Parquet-витрины
├── analysis.py               # PySpark + DuckDB скрипт обработки и формирования витрин
├── app.py                    # Streamlit дашборд
```

## 🚀 Запуск проекта

### 1. Предварительные требования
Убедитесь, что у вас установлены `Python 3.10+` и необходимые зависимости:

```bash
pip install pyspark duckdb streamlit plotly pandas
```

### 2. Запуск ETL-пайплайна
Скрипт выгрузит данные, рассчитает метрики, найдет аномалии и сформирует Parquet-витрины в папке `/app/output/`:

```bash
python analysis.py
```

### 3. Запуск веб-дашборда
После успешного выполнения `analysis.py` запустите Streamlit-приложение:

```bash
streamlit run app.py
```

## 📊 Функционал веб-интерфейса

* **📦 Контроль загрузки:** Статистика по прочитанным CSV-файлам и объёму обработанных записей.
* **🏭 KPI Линий и Цехов:** Анализ количества линий и суммарного числа тревог (Alarms) с возможностью фильтрации по цехам.
* **⏱️ Почасовая динамика:** Распределение событий по типам датчиков.
* **📊 Вариант 5 (Качество):** Рейтинг линий с наибольшей долей проблемных измерений (`bad` + `suspect`).
* **⚙️ Вариант 10 (RPM):** Профиль скоростей вращения вала по типам оборудования.
